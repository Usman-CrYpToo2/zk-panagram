# zk-panagram

[![CI](https://github.com/Usman-CrYpToo2/zk-panagram/actions/workflows/ci.yml/badge.svg)](https://github.com/Usman-CrYpToo2/zk-panagram/actions/workflows/ci.yml)

A word-guessing game in which players prove they know the answer with a zero-knowledge proof, without revealing it. The first valid prover in each round receives a winner NFT; later provers receive a runner-up NFT. The circuit is written in Noir and verified on-chain by a Barretenberg Honk verifier.

## How It Works

1. The owner starts a round with `keccak256(abi.encodePacked(word))`.
2. A player who knows the word generates a proof that their private guess hashes to the round's answer hash. The proof also commits to the player's address and the round number.
3. The player calls `mintReward(proof)`. The contract rebuilds the public inputs from on-chain state and `msg.sender`, verifies the proof, and mints.

Because the sender and round are public inputs, a proof cannot be front-run by another address or replayed in a later round.

## Circuit

[`src/main.nr`](src/main.nr)

| Input | Visibility | Type | Purpose |
|---|---|---|---|
| `guess` | Private | `BoundedVec<u8, 32>` | The word |
| `answer_hash` | Public | `[u8; 32]` | `keccak256` of the answer, as stored by the contract |
| `proof_sender` | Public | `Field` | Binds the proof to `msg.sender` |
| `round` | Public | `Field` | Binds the proof to one round |

The circuit asserts `keccak256(guess.storage(), guess.len()) == answer_hash`. Hashing only `len()` bytes matches Solidity's `abi.encodePacked`, so the zero padding of the bounded vector is never hashed. `proof_sender` and `round` are intentionally unconstrained; their only role is to be fixed into the proof's public inputs.

### Public input layout

The verifier receives 34 values, in the order the circuit declares them:

| Index | Value |
|---|---|
| 0 to 31 | `answer_hash`, one byte per input, right-aligned in a `bytes32` |
| 32 | `proof_sender` |
| 33 | `round` |

`Panagram._buildPublicInputs()` reconstructs exactly this layout, and `publicInputsFor(player, round)` exposes it for clients.

## Usage

Requirements: [Nargo](https://noir-lang.org/docs/getting_started/quick_start) `1.0.0-beta.21`, [Barretenberg](https://github.com/AztecProtocol/aztec-packages/tree/master/barretenberg) `bb` `5.0.0-nightly` (proof generation only), [Foundry](https://book.getfoundry.sh/getting-started/installation), Node.js.

```bash
git clone --recurse-submodules https://github.com/Usman-CrYpToo2/zk-panagram.git
cd zk-panagram
```

### Circuit tests

The tests generate prover addresses through `ethkey`, whose key derivation runs in an oracle server. The `ethkey` CLI starts and stops that server around the test run, so use `ethkey test` instead of `nargo test`.

```bash
nargo check   # fetches dependencies, including ethkey and its CLI
~/nargo/github.com/Usman-CrYpToo2/ethkey-noir/v0.2.0/tools/ethkey.sh install   # once
ethkey test
```

### Proof and verifier generation

```bash
nargo compile
nargo execute
bb write_vk -b target/zkpanagram.json -o out --oracle_hash keccak
bb prove    -b target/zkpanagram.json -w target/zkpanagram.gz -k out/vk -o out --oracle_hash keccak
bb write_solidity_verifier -k out/vk -o contracts/src/verifier.sol
```

`--oracle_hash keccak` is required for on-chain verification. Any change to `main.nr` requires regenerating the verification key, the proof, and the verifier.

### Contract tests

```bash
cd contracts
forge test
```

The suite verifies the proof in `out/` end to end: public inputs match the contract's encoding, the verifier accepts the proof, `mintReward` mints the winner NFT, and a different sender is rejected.

## Security

A self-review found 5 issues, all acknowledged. The most significant is that the public answer hash can be searched offline; [`docs/answer-secrecy.md`](docs/answer-secrecy.md) evaluates commit-reveal and signed-voucher designs that address it. See [`audits/2026-10-self-review.md`](audits/2026-10-self-review.md).
